### GLOBAL ERPNEXT SCHEMA ###
# This file contains the standard ERPNext table schema organized by module.
# The AI uses this to understand table names, key columns, and relationships.
# Format: TABLE_NAME: column1 (type), column2 (type), ... | CHILD OF: parent_table

## ============================================================
## MODULE: SELLING
## ============================================================

`tabCustomer`: name (PK), customer_name (Data), customer_type (Select), customer_group (Link), territory (Link), default_currency (Link), default_price_list (Link), tax_id (Data), disabled (Check)

`tabSales Order`: name (PK), customer (Link→Customer), customer_name (Data), transaction_date (Date), delivery_date (Date), company (Link), currency (Link), grand_total (Currency), net_total (Currency), total_qty (Float), status (Select), per_delivered (Percent), per_billed (Percent), territory (Link), sales_partner (Link)

`tabSales Order Item`: name (PK), parent (Link→Sales Order), item_code (Link→Item), item_name (Data), qty (Float), rate (Currency), amount (Currency), delivery_date (Date), warehouse (Link→Warehouse), uom (Link), net_amount (Currency) | CHILD OF: `tabSales Order`

`tabSales Invoice`: name (PK), customer (Link→Customer), customer_name (Data), posting_date (Date), due_date (Date), company (Link), currency (Link), grand_total (Currency), net_total (Currency), outstanding_amount (Currency), total_qty (Float), status (Select), is_return (Check), return_against (Link), territory (Link), cost_center (Link), sales_partner (Link), custom_sales_person (Link)

`tabSales Invoice Item`: name (PK), parent (Link→Sales Invoice), item_code (Link→Item), item_name (Data), qty (Float), rate (Currency), amount (Currency), warehouse (Link→Warehouse), uom (Link), net_amount (Currency), cost_center (Link), income_account (Link) | CHILD OF: `tabSales Invoice`

`tabQuotation`: name (PK), quotation_to (Select), party_name (Link), transaction_date (Date), valid_till (Date), company (Link), grand_total (Currency), status (Select), order_type (Select)

`tabQuotation Item`: name (PK), parent (Link→Quotation), item_code (Link→Item), qty (Float), rate (Currency), amount (Currency) | CHILD OF: `tabQuotation`

`tabDelivery Note`: name (PK), customer (Link→Customer), posting_date (Date), company (Link), grand_total (Currency), status (Select), is_return (Check), per_billed (Percent)

`tabDelivery Note Item`: name (PK), parent (Link→Delivery Note), item_code (Link→Item), qty (Float), rate (Currency), amount (Currency), warehouse (Link→Warehouse), against_sales_order (Link), against_sales_invoice (Link) | CHILD OF: `tabDelivery Note`

## ============================================================
## KEY RELATIONSHIPS & JOIN PATTERNS
## ============================================================

# Sales Flow: Customer → Quotation → Sales Order → Delivery Note → Sales Invoice → Payment Entry
# Purchase Flow: Supplier → Purchase Order → Purchase Receipt → Purchase Invoice → Payment Entry
# Stock: All stock movements tracked in `tabStock Ledger Entry` via voucher_type + voucher_no
# Accounting: All financial transactions tracked in `tabGL Entry` via voucher_type + voucher_no
# Child tables always join via: child.parent = parent.name
# Stock Ledger to Invoice: sle.voucher_no = si.name AND sle.item_code = sii.item_code
